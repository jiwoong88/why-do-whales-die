# 왜 죽는 고래? (Why Whales Die)

배를 피해 숨 쉬러 올라가는 대왕고래 게임. 선박 충돌은 대왕고래의 가장 큰 사망 원인 중
하나이고, 해마다 약 2만 마리의 고래가 배에 치여 죽는다. 이 사실을 카피가 아니라
**메커니즘**으로 박았다 — 숨을 쉬려면, 배가 다니는 수면으로 올라가야 한다.

**플레이: https://gorae-hwamulseon.vercel.app**

## 조작법

| | |
|---|---|
| 🕹️ 헤엄 | 왼쪽 화면(방향패드)을 누른 방향으로 즉시 헤엄침. 데스크톱은 화살표/WASD |
| 💨 숨쉬기 | 오른쪽 **숨쉬기** 버튼을 길게 눌러 수면에서 호흡. 부상 중에는 거의 못 움직인다 |
| 🦐 크릴 | 흩어진 초록 크릴을 먹어 허기를 채움 |
| ⏎ 재시작 | Enter 또는 게임오버 화면 탭 |

## 종료 조건 — 셋 다 실제 위협이다

- **충돌** — 화물선·어선에 치임 (날이 갈수록 배가 늘고 빨라진다)
- **질식** — 산소 0. 잠수 중 계속 닳고, 수면에서 숨 쉬어야 회복된다
- **굶주림** — 허기 0. 크릴을 못 찾으면 죽는다

점수는 **헤엄친 거리**로 오른다(가만히 있으면 0). 죽으면 그 판의 점수와 생존 일수가
남고, 전 세계 랭킹에 올릴 수 있다. 죽을 때마다 고래에 대한 사실이 하나씩 풀린다(18개).

## 기술 구성

- **단일 HTML 파일** — `index.html` 하나에 전부 들어 있다
- **바닐라 캔버스** — 프레임워크·라이브러리 없음
- **빌드 도구 없음** — 트랜스파일도, 번들링도, `node_modules`도 없다. 파일을 브라우저로
  열면 그대로 돌아간다
- **서버는 랭킹만** — 전 세계 랭킹과 추천 집계에만 Supabase REST를 쓴다. 키가 없으면
  자동 비활성화되고 게임은 그대로 돌아간다
- 지도·고래·배·크릴은 전부 코드 렌더(canvas). 외부 이미지 에셋이 아니다
- 배포는 Vercel

## ⚠️ 커밋 이력에 대한 고지 — 이 저장소의 이력은 복원된 것입니다

**개발 기간 동안 버전 관리를 깃이 아니라 `vNN_백업.html` 파일 스냅샷으로 했습니다.
제출을 위해 각 백업 파일의 실제 수정 시각과 개발 로그(`로그.md`)에 남긴 당시 변경
사유를 근거로 커밋 이력을 복원했습니다. 커밋 날짜는 원본 파일의 수정 시각이며,
저장소 자체는 2026년 8월에 생성되었습니다. 원본 스냅샷 파일은 `snapshots/`에 그대로
두었고, 커밋과 원본의 대조표는 `RESTORATION.md`에 있습니다.**

숨기지 않는 것이 이 복원의 전제입니다. 아래에 자세히 적습니다.

### 왜 깃을 안 썼나

만든 사람이 개발자가 아닙니다. MV 디렉터·영상 편집자이고, 이 게임은 AI와 함께
만들었습니다. 편집 일에서 하던 방식대로 — 고칠 때마다 현재 파일을 `vNN_백업.html`로
복사해 두고 다음 판을 만드는 식으로 관리했습니다. 되돌리고 싶으면 그 파일을 다시
`index.html`에 덮어썼습니다(실제로 v24, v84에서 그렇게 롤백했습니다).
깃을 써야 한다는 걸 나중에 알았고, 그때는 이미 백업 파일이 100판 가까이 쌓여 있었습니다.

### 어떻게 관리했나

- `index.html` 한 파일이 항상 "현재 판"
- 판이 바뀔 때마다 직전 상태를 `vNN_백업.html`로 스냅샷
- 매 판의 **무엇을 왜 바꿨는지**를 `로그.md`에 `## vNN — 제목` 형식으로 기록.
  피드백 원문, 원인 진단, 결정과 그 이유, 검증 방법까지 적혀 있습니다.
  이 저장소의 커밋 메시지는 전부 이 로그에서 옮긴 것입니다

### 복원에 무엇을 근거로 썼나

1. **커밋 날짜** = 그 백업 파일의 실제 수정 시각(mtime). 지어낸 값이 아니라 파일
   시스템에서 읽었고, 옮기는 동안 mtime을 보존했습니다. `snapshots/` 안의 파일이
   그 시각을 아직 갖고 있으므로 `ls -l snapshots/`로 대조할 수 있습니다
2. **커밋 순서** = 판 번호가 아니라 **파일 수정 시각 순서**
3. **커밋 메시지** = `로그.md`의 해당 항목. 그럴듯하게 다시 쓰지 않았습니다
4. **커밋 내용** = 그 판 백업 파일의 내용 그대로(59개 전부 해시 일치 확인)

되돌린 이력도 지우지 않았습니다. 예를 들어 `v83 고래 큐트화` 바로 다음 커밋이
`v84 v83 큐트화 롤백 — 무섭다는 피드백`입니다. 잘 풀린 판만 남기면 그건 복원이 아닙니다.

### 복원하지 못한 구간

백업 파일이 남아 있지 않아 되살리지 못한 판이 있습니다. **없는 판을 지어내지
않았습니다.**

- **v2 ~ v5** — 탑뷰 전환, 데이터 시각화 룩, 대한해협 실측 지도, 칠레 안쿠드만 무대
- **v7 ~ v27** — Spilhaus 투영 구현, 미니 모토웨이 스타일 전면 리디자인, 육각 그리드,
  고래 시야 안개, 모바일 방향패드 도입
- **v85 ~ v105** — 랭킹 보강, 일시정지, 피버 시스템, 호흡 안내 조건 반복 수정

세 구간 모두 `로그.md`에는 당시 기록이 남아 있고, 결과물은 최종 `index.html`(v106)에
들어 있습니다. 코드 스냅샷만 없습니다.

### 어디서 검증할 수 있나

| | |
|---|---|
| `RESTORATION.md` | 커밋 ↔ 원본 파일 ↔ 수정 시각 ↔ 로그 근거 대조표(전 커밋) |
| `snapshots/` | 원본 백업 html 59개. 지우지 않고 mtime까지 그대로 보존 |
| `로그.md` | 개발 로그 원문. 커밋 메시지의 출처 |

```bash
# 커밋 내용이 원본 스냅샷과 같은지
shasum snapshots/v83_백업.html
git show 7c49437:index.html | shasum      # 같은 해시여야 함

# 커밋 날짜가 원본 파일 수정 시각과 같은지
ls -l snapshots/
git log --format="%ad %s" --date=short
```

`로그.md`는 주최사가 개발 로그 원문 포함을 요구해(2026-08-04 운영사무국 회신)
편집 없이 그대로 포함했습니다.
